# Real Estate Management System (REMS)

An internal real estate management system built for company use on a local network (LAN).
Manage properties, customers, appointments, and generate reports — all from a single web interface accessible from any computer on the office network.

> **⚠ Backup Notice**
> Backup is not automated. The MySQL database and all uploaded media files
> (`backend/uploads/`) must be backed up **manually** on a regular schedule.
> See [DEPLOYMENT.md](./DEPLOYMENT.md#10-database-backup) for step-by-step instructions.
> Deleted records and uploaded files are permanently removed — there is no recycle bin.

---

## What the System Does

| Module | Status | Features |
|---|---|---|
| **Properties** | ✅ Fully implemented | Add, edit, delete listings · upload photos and videos · track status (available / sold / rented / reserved) |
| **Customers** | ✅ Fully implemented | CRM lead pipeline · assign to agents · track status (new → interested → closed) |
| **Appointments** | ✅ Fully implemented | Schedule property viewings · track status lifecycle · conflict detection |
| **Reports** | ✅ Fully implemented | Dashboard KPIs · property reports · customer pipeline · agent performance · financial overview |
| **Users** | ✅ Fully implemented | Role-based access (Admin / Manager / Employee) · password management · activity audit log |
| **Media** | ✅ Fully implemented | Multi-image gallery (up to 10 per property) · video upload (MP4/WebM, up to 5 per property) |
| **Contracts** | 🚧 Not in this version | Database schema and tables are present, but the Contracts module has no working UI or API — all contract endpoints return HTTP 501. Financial/payment recording is also not available in this version. |

> **Note on financial KPIs:** The dashboard and financial report display contract and revenue totals.
> Since the Contracts module is not yet active, these figures will always show zero in this version.
> All other KPIs (properties, customers, appointments) are live and accurate.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite + Tailwind CSS |
| Backend | Node.js 18+ + Express 4 |
| Database | MySQL 8 |
| Auth | JWT (access token 8h + refresh token 7d) · HttpOnly cookie · server-side revocation |
| File uploads | Multer (images: JPEG/PNG/WebP · videos: MP4/WebM, max 500 MB each) |
| Process manager | PM2 or NSSM (Windows Service) |

## Quick Start (Development)

```bash
# 1. Install all dependencies
npm install --prefix backend
npm install --prefix frontend

# 2. Configure backend
cp backend/.env.example backend/.env
# Edit backend/.env with your DB credentials

# 3. Create DB schema + seed admin user
cd backend
node scripts/migrate-live-db.js
node scripts/seed-admin.js

# 4. Start backend (port 5000)
npm run dev --prefix backend

# 5. Start frontend dev server (port 3000)
npm run dev --prefix frontend

# 6. Open browser
# http://localhost:3000
```

> **⚠ Change default credentials immediately on any production system:**
>
> | Field | Default value |
> |---|---|
> | Email | `admin@test.com` |
> | Password | `Admin@123456` |
>
> Go to Users → Edit your account → Change Password after first login.

# Access from any office PC:

## User Roles

| Role | Access |
|---|---|
| **Admin** | Full access: users, properties, customers, appointments, reports, settings |
| **Manager** | Properties, customers, appointments, reports — no user management |
| **Employee** | Own properties, customers, and appointments only |

## API

All endpoints are at `/api/v1/`.

| Resource | Endpoints | Status |
|---|---|---|
| Auth | `POST /auth/login` · `/auth/refresh` · `/auth/logout` · `GET /auth/me` · `POST /auth/change-password` · `POST /auth/register` | ✅ Working |
| Users | `GET/POST /users` · `GET/PUT/DELETE /users/:id` · `PATCH /users/:id/password` · `PATCH /users/:id/deactivate` | ✅ Working |
| Properties | Full CRUD + `/images` + `/videos` + `/status` | ✅ Working |
| Customers | Full CRUD + `/status` + `/assign` + `/pipeline` | ✅ Working |
| Appointments | Full CRUD + `/status` + `/reschedule` + `/assign` | ✅ Working |
| Reports | `/reports/dashboard` · `/reports/properties` · `/reports/customers` · `/reports/agents` · `/reports/financials` | ✅ Working (financials always empty — see note above) |
| Activities | `GET /activities` | ✅ Working |
| Contracts | All routes | 🚧 Returns HTTP 501 — not implemented |

Health check: `GET /health`
